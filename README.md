# Email Bridge Bot

Веб-панель и фоновый обработчик, который проверяет входящую почту по IMAP и пересылает письма в Telegram или MAX по правилам с ключевыми словами.

## Что реализовано

- Веб-панель на русском языке: обзор, настройки, правила и журнал доставок.
- Вход по паролю администратора из `.env`; формы защищены CSRF.
- IMAP SSL-подключение, проверка непрочитанных писем с интервалом 15–3600 секунд.
- Поиск ключевых слов без учёта регистра в теме и текстовой части письма.
- Отправка в Telegram Bot API и MAX Bot API.
- Повторная попытка при ошибке доставки: письмо не помечается обработанным, пока все совпавшие правила не доставлены.
- Журнал успешных и неуспешных отправок.
- Секреты в форме скрыты: пустое поле не затирает ранее сохранённый токен или пароль.

## Быстрый запуск (Linux)

```bash
cd email-bridge-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Отредактируйте `.env`: задайте `SECRET_KEY` и `ADMIN_PASSWORD`. Не публикуйте `.env` и не отправляйте его в GitHub.

Запуск панели:

```bash
source .venv/bin/activate
python app.py
```

Панель слушает порт `10000`. Для локального теста откройте `http://127.0.0.1:10000`, а на сервере — `http://IP_СЕРВЕРА:10000`. Для постоянной эксплуатации предпочтительно закрыть прямой доступ к порту извне, поставить Nginx с HTTPS перед приложением и установить `COOKIE_SECURE=1`. Если нужен прямой доступ по IP:10000, откройте TCP-порт 10000 в firewall и ограничьте доступ доверенными IP-адресами.

В отдельном терминале запустите обработчик:

```bash
cd email-bridge-bot
source .venv/bin/activate
python mail_worker.py
```

## Настройка MAX

Создайте чат-бота MAX и получите токен. В панели вставьте токен MAX. В поле получателя:

- `123456` или `chat:123456` — ID группового чата/канала;
- `user:123456` — ID пользователя для личного диалога.

Бот должен иметь право писать в соответствующий диалог/чат. Отправка реализована через официальный `POST https://platform-api2.max.ru/messages`, токен передаётся заголовком `Authorization`.

## Настройка Telegram

Создайте бота через BotFather, вставьте токен в настройки. Получатель — числовой `chat_id`. Пользователь должен предварительно открыть диалог с ботом; в группе бот должен быть добавлен.

## systemd

Скопируйте проект в `/opt/email-bridge-bot`, создайте `.venv`, установите зависимости и заполните `.env`. В unit-файлах замените `ubuntu` на пользователя сервера, если он другой:

```bash
sudo cp deploy/email-bridge-web.service /etc/systemd/system/
sudo cp deploy/email-bridge-worker.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now email-bridge-web email-bridge-worker
sudo systemctl status email-bridge-web email-bridge-worker
```

Логи:

```bash
journalctl -u email-bridge-web -f
journalctl -u email-bridge-worker -f
```

## Важно перед эксплуатацией

- SQLite и секреты в текущей версии не шифруются на уровне приложения. Ограничьте права на каталог проекта и резервные копии БД; используйте защищённый сервер.
- Панель не должна публиковаться напрямую в интернет без HTTPS и дополнительной сетевой защиты.
- IMAP UID хранится в локальной БД как ключ обработки. Не удаляйте БД, если не хотите повторно обработать старые письма.
- Если один из нескольких адресатов не получил письмо, обработчик повторит попытку для всех совпавших правил; возможен повтор для уже успешно доставленного адресата. Это предпочтительнее потери уведомления, но не обеспечивает exactly-once доставку.
- MAX требует корректного ID и прав бота; реальную доставку следует подтвердить тестовым письмом после ввода токена.
